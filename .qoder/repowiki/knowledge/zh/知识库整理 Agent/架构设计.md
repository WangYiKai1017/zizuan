- **分层架构**：采用 `Routes` (FastAPI) -> `Runner` (SSE/Session) -> `Agent` (LangGraph Logic) -> `Service` (Business Rules) 的四层调用链。
- **编排核心**：`kb_organizer_graph.py` 定义 `plan-execute-observe` 循环状态机，通过 `should_continue` 条件边控制任务流转。
- **状态管理**：`KBOrganizerState` (Pydantic) 作为全局共享状态，维护任务计划、文档索引、合并记录及矛盾项，确保节点间数据一致性。
- **业务逻辑下沉**：`KBOrganizationService` 封装 LLM 交互（去重、矛盾解析）与文件操作（链接校验、原子备份），实现 Agent 逻辑与底层实现的解耦。
- **依赖注入**：Agent 通过构造函数接收 `LLMService` 和 `KBOrganizationService`，便于测试与配置隔离。
