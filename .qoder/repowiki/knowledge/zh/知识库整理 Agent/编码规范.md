- 采用固定任务清单模式，在 `_TASK_DEFINITIONS` 中预定义 8 个标准化整理步骤，而非由 LLM 动态生成计划。
- 遵循“工作副本”安全模式，所有修改在 `_temp` 目录进行，仅在 `finalize_swap` 阶段通过备份原目录实现原子替换。
- 统一使用 `MarkdownFileManager` 和 `FileOperations` 抽象层处理文件 I/O，避免在 Agent 或 Service 中直接操作 `pathlib` 或 `os`。
- 在 Service 层对 LLM 返回结果进行严格的 JSON 提取与结构化校验 (`_extract_json`)，并包含业务规则兜底逻辑（如 `_is_valid_duplicate_group`）。
